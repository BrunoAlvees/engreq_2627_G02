# 2.5 Pressupostos e dependências

**Responsável:** Liane Duarte · **Atualizado em:** 04/11/2026 · **Estado:** rascunho, a completar depois de fechados os requisitos e os casos de uso
**Fontes:** códigos de fonte de [requisitos/README.md](../requisitos/README.md), [perguntas em aberto](../requisitos/PerguntasEmAbertoPT.md) (PA-nn), [dúvidas sobre os processos atuais](../tecnicas/DuvidasProcessosAtuaisPT.md) (DV-nn), [2.4](2.4_RestricoesConcecaoImplementacaoPT.md)

Esta secção lista os fatores de que os requisitos dependem, mas que o projeto não controla.
- Um **pressuposto (AS)** é algo que o grupo considera verdadeiro sem o ter confirmado com os stakeholders.
- Uma **dependência (DE)** é um serviço, componente, decisão ou regra externa de que o sistema precisa.

Se um destes pontos se revelar falso ou mudar, os requisitos indicados na coluna "Impacto se falhar" têm de ser revistos. As **restrições certas** (ex.: o sistema não emite faturas, NFR-18) ficam na secção 2.4, não aqui.

Estados: **A validar** (falta confirmar com o cliente ou stakeholder) · **Confirmado** (passa a facto ou a requisito e sai desta lista) · **Falso** (rever os requisitos afetados).

## 2.5.3 Como manter esta lista

- **Durante o trabalho:** sempre que um requisito, um caso de uso ou uma pré-condição depender de algo não confirmado, acrescentar aqui uma linha com o próximo número livre. Os IDs nunca são reutilizados.
- **Depois da próxima sessão com o cliente:** os pressupostos confirmados passam a "Confirmado" (com a fonte) e são retirados do SRS final ou passam a requisito. Os falsos levam à revisão dos requisitos indicados.
- **Antes de passar para o Word:** confirmar que os IDs FR/NFR citados ainda existem, porque os requisitos foram renumerados a 28/10 e a 30/10.
