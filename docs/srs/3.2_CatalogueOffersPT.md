# 3.2 Catálogo e ofertas

**Responsável:** Bruno Alves · **Atualizado em:** 12/11/2026 · **Estado:** rascunho para o relatório
**Fontes:** [RF02_CatalogoOfertasPT.md](../requisitos/RF02_CatalogoOfertasPT.md) (requisitos, fontes e estado) · critérios de aceitação em [12.4](12.4_AcceptanceCriteriaPT.md)

## 3.2.1 Descrição
Esta funcionalidade permite a cada produtor manter o seu catálogo (cabazes, produtos extra e produtos pontuais) e definir, para cada produto, as variantes, o tipo de preço, a periodicidade e a capacidade. Hoje o catálogo está num Google Forms: muitas opções acabam em texto livre e há produtos que existem mas não estão listados (ex.: cogumelos secos).

**Prioridade: Alta** (4 dos seus 6 requisitos são Must).

## 3.2.2 Sequências estímulo/resposta

*Tabela – Sequências estímulo/resposta da funcionalidade 3.2*

| Ação do utilizador (estímulo) | Resposta do sistema |
|---|---|
| O produtor cria um produto e define o tipo, o preço e a periodicidade | Acrescenta o produto ao catálogo do produtor, disponível para o ciclo seguinte |
| O produtor reutiliza o catálogo do ciclo anterior | Copia os produtos, para o produtor só ajustar preços e datas |
| O produtor indica quantos coprodutores consegue abastecer com um produto | Aceita subscrições até esse número, ou até à capacidade máxima da AMAP |
| Um coprodutor tenta subscrever um produto cuja capacidade se esgotou | Propõe colocá-lo na lista de espera desse produto e avisa-o quando abrir uma vaga |
| O coprodutor abre um produto | Mostra a ficha: descrição, certificação, conservação, origem e preço com IVA |
| O produtor publica uma oferta pontual (ex.: um excedente) com uma quantidade disponível | Avisa os coprodutores e aceita encomendas até a quantidade se esgotar; depois fecha a oferta |

### Especificação dos casos de uso
Os dois casos de uso principais estão detalhados abaixo.

*Tabela – Caso de uso: Gerir catálogo (FR-11 a FR-14)*

| | |
|---|---|
| **Nome** | Gerir catálogo |
| **Descrição** | Um produtor cria ou atualiza os produtos que oferece a uma AMAP para o ciclo seguinte. |
| **Atores** | Produtor (principal) |
| **Pré-condições** | 1. O produtor está ativo na AMAP. |
| **Fluxo principal** | 1. O produtor abre o seu catálogo.<br>2. O produtor cria um produto e escolhe o tipo: cabaz, extra ou pontual.<br>3. O produtor preenche o nome, a descrição, as variantes (ex.: tamanho, nível de preço) e o tipo de preço (quota fixa, por unidade ou por kg).<br>4. O produtor define a periodicidade (ex.: quinzenal, mensal, só em certos meses).<br>5. O produtor indica quantos coprodutores consegue abastecer com esse produto.<br>6. O sistema valida os dados e acrescenta o produto ao catálogo do ciclo seguinte. |
| **Fluxos alternativos** | A1 (passo 2): o produtor reutiliza o catálogo do ciclo anterior; o sistema copia os produtos e o produtor só ajusta preços e datas.<br>A2 (passo 2): o produtor edita ou desativa um produto existente. |
| **Exceções** | 1. Faltam campos obrigatórios (ex.: preço): o sistema pede ao produtor que os preencha.<br>2. A capacidade indicada é superior à capacidade máxima da AMAP: o sistema avisa o produtor e usa o limite da AMAP. |
| **Pós-condições** | 1. O produto está no catálogo do produtor e fica visível para os coprodutores quando o ciclo abrir. |

*Tabela – Caso de uso: Publicar oferta pontual (FR-16)*

| | |
|---|---|
| **Nome** | Publicar oferta pontual |
| **Descrição** | Um produtor oferece um excedente ou um produto novo fora das subscrições, e os coprodutores encomendam-no. |
| **Atores** | Produtor (principal), coprodutor |
| **Pré-condições** | 1. O produtor está ativo na AMAP. |
| **Fluxo principal** | 1. O produtor cria uma oferta pontual com o produto, o preço e a quantidade disponível.<br>2. Se quiser, o produtor limita a oferta a um número máximo de coprodutores ou a uma quantidade máxima por pessoa.<br>3. O sistema publica a oferta e avisa os coprodutores da AMAP.<br>4. Um coprodutor encomenda uma quantidade.<br>5. O sistema regista a encomenda e desconta-a da quantidade disponível.<br>6. Quando a quantidade se esgota, o sistema fecha a oferta. |
| **Fluxos alternativos** | A1 (qualquer passo): o produtor altera a quantidade disponível; o sistema atualiza-a.<br>A2 (passo 6): o prazo de encomenda termina antes de a quantidade se esgotar; o sistema fecha a oferta. |
| **Exceções** | 1. O coprodutor encomenda mais do que o disponível ou do que o limite por pessoa: o sistema recusa a encomenda e mostra o máximo permitido. |
| **Pós-condições** | 1. As encomendas ficam registadas e entram na entrega e no pagamento seguintes de cada coprodutor. |

## 3.2.3 Requisitos funcionais

*Tabela – Requisitos funcionais da funcionalidade 3.2 (M = Must, S = Should, C = Could)*

| ID | Requisito | Ator | Prioridade |
|---|---|---|---|
| FR-11 | O sistema deve permitir ao produtor gerir o seu catálogo de cabazes, produtos extra e produtos pontuais, sem uma lista fechada de produtos. | Produtor | M |
| FR-12 | O sistema deve permitir ao produtor oferecer vários tipos de cabaz e variantes de cada produto. | Produtor | M |
| FR-13 | O sistema deve permitir definir o tipo de preço e a periodicidade de cada produto. | Produtor | M |
| FR-14 | O sistema deve permitir definir uma capacidade máxima por produto e por AMAP e gerir uma lista de espera quando é atingida. | Produtor | M |
| FR-15 | O sistema deve mostrar ao coprodutor a ficha de cada produto. | Coprodutor | S |
| FR-16 | O sistema deve permitir ao produtor publicar ofertas pontuais (ex.: excedentes ou produtos novos), que os coprodutores podem encomendar fora da subscrição. | Produtor, coprodutor | S |

*Os critérios de aceitação de cada requisito estão no Apêndice 12.4.*
